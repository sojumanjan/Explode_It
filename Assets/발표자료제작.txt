4번 슬라이드: AI 협업 방식
도구: Claude Code + Unity MCP. AI가 에디터를 직접 조작해서 씬 배치, 에셋 설정, 렌더링 확인까지 했습니다.
역할 분담: 기획 판단과 플레이 테스트는 사람이 하고, 구현과 반복 작업은 AI가 했습니다.
CLAUDE.md에 "플레이 테스트는 무조건 사람이 한다", "밸런스 수치는 코드에 넣지 않는다" 같은 규칙을 박아 두었습니다.
AI 기억 관리: 인수인계 문서(handoff)와 규칙 문서로, 세션이 바뀌거나 컴퓨터가 달라져도 이어서 작업했습니다.
그림과 소리도 AI로: 이미지 AI로 뽑은 그림을 AI가 배경 제거하고 크기를 맞췄습니다. 배경음은 Varco로 만들었습니다.
5번 슬라이드: AI가 틀렸을 때 (사례 고르기)

“AI를 그대로 믿지 않고 검증했다”를 보여 주는 게 목적입니다. 데브로그 형식 그대로 문제 → 원인 → 해결 → 수치로 보여 주세요. 추천 사례는 이렇습니다.

빌드 용량: "압축"으로 설정된 그림이 실제로는 무압축으로 빌드되고 있었습니다(가로세로가 4의 배수가 아니면 압축 불가). 빌드 리포트로 찾아내 262MB → 230MB 이하로 줄였습니다. 숫자가 있어서 가장 설득력이 있습니다.
효과음 늘어짐 버그: 슬로모션 도중 상태가 바뀌면 소리 높이가 안 돌아오는 버그였습니다. 빌드로 직접 플레이하다 발견했고, AI에게 원인을 추적시켜 고쳤습니다. "사람이 테스트하고 AI가 추적"의 좋은 예입니다.
크레딧 곡 동기화: 미리 잰 값에 맞췄더니 실제 게임에서 어긋났습니다. 그래서 실행 중에 계산하는 방식으로 바꿨습니다.
마지막에 “AI 수정 264건을 모두 기록했다”는 숫자를 보여 주면 과정이 탄탄해 보입니다.

데이터 기반 설계: 무기, 적, 웨이브, 업적을 모두 ScriptableObject로 만들어서, 코드 수정 없이 밸런스를 조정했습니다(165개).
