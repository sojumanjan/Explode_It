# Explode It 기획안

2026년 9월 30일 · @한지훈

## 원페이저 요약

**Explode It은 1초 뒤 터지는 폭탄으로 적의 미래 위치를 읽고, 멈추지 않고 움직이며 살아남는 탑다운 스테이지형 로그라이트 슈터 게임.**

| 항목 | 내용 |
| --- | --- |
| 한 줄 컨셉 | 에임 대신 예측, 장전 대신 무빙 |
| 핵심 루프 | 적 움직임 읽기 → 폭탄 투척 → 회피 무빙 → 1초 뒤 폭발 → 웨이브 클리어 → 탈출할지 더 버틸지 선택 |
| 플레이 시간 | 스테이지당 3~5분, 스테이지 약 6개. |

차별점은 두 가지다. 첫째, 공격의 결과가 1초 뒤에 나오기 때문에 플레이어의 시선이 "지금 적이 있는 곳"이 아니라 "1초 뒤 적이 있을 곳"으로 옮겨간다. 둘째, 웨이브를 다 깬 뒤에도 스테이지에 남아 더 버티면 재화가 쌓이는 구조로, 매 스테이지 끝에 위험과 보상 사이의 선택이 생긴다.

## 게임 개요

폭탄을 다루는 주인공이 고블린과 골렘이 사는 판타지 세계를 스테이지 단위로 돌파하는 게임이다.

| 항목 | 내용 |
| --- | --- |
| 제목 | Explode It |
| 장르 | 탑다운 아레나 슈터 + 스테이지형 로그라이트 |
| 엔진 | Unity 6000.5.6f1, 2D URP |
| 플랫폼 | PC |
| 테마 | 판타지. 주인공은 폭탄 전문가, 적은 고블린, 골렘 계열 |
| 아트 | 픽셀아트, AI 생성 에셋 사용 |
| 조작 | 이동(WASD), 폭탄 투척(마우스 클릭, 커서 위치로) |
| 스테이지 길이 | 3~5분 |
| 난이도 구조 | 노멀 전 스테이지 클리어 시 하드모드 해금, 처음부터 재도전 |

## 핵심 메카닉

모든 메카닉은 "1초 뒤를 읽고, 계속 움직인다"는 한 문장을 강화하도록 설계한다.

**1초 딜레이 폭탄**

- 클릭한 위치로 폭탄을 던지고, 착지 후 1초 뒤 폭발한다. 딜레이 값은 무기 데이터로 관리해 0.8~1.2초 범위에서 테스트한다.
- 착지 순간부터 폭발 범위를 바닥에 표시한다. 플레이어는 판정 범위를 정확히 보고 예측해야 공정하다고 느낀다.
- 자폭 판정은 없다. 스트레스 요소만 늘리고 핵심 재미인 예측과 무관하기 때문이다.

**한 방 사망**

- 플레이어와 적은 한 번의 피격으로 쓰러진다. 긴장감의 원천이며, 레퍼런스와 공유하는 뼈대다.
- 추후 실드 시스템을 검토한다. 확장을 고려해 피격 처리는 처음부터 "피격 → 판정 → 사망" 단계를 분리해 둔다.

**무빙**

- 장전이 없으므로 쿨타임 동안 할 수 있는 건 이동뿐이다. 쿨타임이 곧 회피와 자리 잡기 시간이 된다.
- 적의 공격은 모두 예고 동작을 가진다. 플레이어가 무빙으로 피할 수 있어야 한 방 사망이 공정해진다.

**무기 시스템 (쿨타임형)**

무기는 우열이 아닌 플레이 스타일의 차이다. 아래 네 가지 수치 조합으로 무기를 정의한다.

| 수치 | 의미 | 예시 무기 성향 |
| --- | --- | --- |
| 보유 개수 | 쿨타임 전까지 연속으로 던질 수 있는 폭탄 수 | 소형 폭탄 3개 연속 투척 |
| 폭발 범위 | 폭발 반경 | 대형 폭탄 1개, 넓은 범위 |
| 연사 속도 | 연속 투척 사이 간격 | 빠른 투척, 좁은 범위 |
| 쿨타임 | 보유 개수가 다시 차는 시간 | 긴 쿨타임, 큰 한 방 |

초기 무기는 균형 스타일의 무기 1종으로 시작하며, 스테이지 및 업적 달성에 따라 무기가 하나씩 해금된다.

## 스테이지와 웨이브 구조

스테이지는 정해진 웨이브를 모두 버티면 클리어된다.

**스테이지 구성**

- 노멀 모드는 4스테이지로 시작한다(초안). 스테이지마다 맵과 등장 적 조합이 다르고, 체감 난이도는 비슷하게 유지한다.
- 스테이지는 웨이브 6~8개, 총 3~5분 분량으로 구성한다. 웨이브별 적 종류, 수, 등장 위치, 간격은 모두 데이터로 정의한다.
- 새 적은 스테이지마다 1~2종씩 추가해, 스테이지 진행이 곧 새로운 예측 과제의 등장이 되도록 한다.

**하드모드**

- 노멀 4스테이지를 모두 클리어하면 해금되고, 1스테이지부터 다시 시작한다.
- 같은 맵에 적 이동 속도, 스폰 밀도, 예고 시간을 조정한 변형을 적용한다. 가능하면 폭탄 범위를 보고 피하는 적 같은 하드 전용 행동을 1~2개 추가한다.

### [추가 가능한 과열 시스템]

과열 구간은 이 게임의 두 번째 차별점이다. 탈출 포탈은 언제든 열려 있고, 머무는 시간만큼 재화와 위험이 함께 오른다. 현재 단계에서는 재화의 쓰임새가 명확하지 않아 임시 요소로 둔다.

**과열 구간 (머무르기 보상, 제안)**

- 마지막 웨이브를 클리어하면 탈출 포탈이 열리고 과열 게이지가 오르기 시작한다.
- 과열 단계가 오를수록 적 스폰 밀도와 강한 적 비율이 오르고, 처치당 재화 획득량도 함께 오른다.
- 과열 중 사망하면 런이 끝난다. 한 방 사망 게임에서 과열은 "런 전체를 건 욕심"이 되고, 이 긴장감이 핵심이다.
- 화면에 현재 과열 단계와 누적 재화를 크게 표시해, 플레이어가 "한 번만 더"를 의식적으로 고르게 한다.

## 적 설계

적은 각자 "1초 뒤 위치를 읽는 방법"을 다르게 시험하도록 설계한다. 적이 무작위로 움직이면 예측이 운으로 바뀌기 때문이다.

**설계 원칙**

1. 모든 적의 이동은 규칙적이고 읽을 수 있어야 한다. 무작위성은 등장 위치와 조합에만 둔다.
2. 모든 공격에는 예고 동작이 있다. 예고 시간은 적 데이터로 관리하고, 하드모드에서 줄인다.
3. 적 하나는 예측 과제 하나를 담당한다. 새 적이 나오면 플레이어가 새로운 읽기 방식을 배워야 한다.
4. 적의 재미는 조합에서 나온다. 웨이브 설계는 "어떤 예측 과제를 동시에 던질지"를 정하는 작업이다.

**적 종류 초안**

| 적 | 등장 | 움직임 | 공격 |
| --- | --- | --- | --- |
| 고블린 궁수 | 1스테이지 | 플레이어를 향해 직진. 일정 거리에 멈춰서 원거리 화살 공격. | 원거리 |
| 고블린 돌격병 | 1스테이지 | 멈춤 → 예고 → 직선 돌진 | 돌진 충돌 |
| 고블린 저격수 | 2스테이지 | 궁수와 비슷하지만 공격 사거리가 매우 긺. 공격 경로를 미리 보여줌. | 원거리 투척 |
| 박쥐 무리 | 2스테이지 | 원을 그리며 선회 | 근접 |
| 돌 골렘 | 3스테이지 | 느린 직진. 3번의 공격을 받아야 사망. | 지면 강타(범위) |
| 분열 슬라임 | 3스테이지 | 튀어 오르며 이동, 처치 시 분열 | 근접 |
| 고블린 주술사 | 4스테이지 | 순간이동 후 시전 | 탄막 |

## 진행 시스템

성장보다 선택지의 확장을 주는 구조다. 판 안에서는 재화로 특수 능력을 사고, 판 밖에서는 업적으로 아티팩트를 해금한다.

**판 내부: 재화와 특수 능력**

- 재화는 적 처치와 과열 구간에서 얻고, 스테이지 사이 상점에서 쓴다. 판이 끝나면 사라진다.
- 상점 상품은 수치 강화보다 플레이 방식을 바꾸는 능력 위주로 구성한다. 예시로 폭발 후 잔불 장판, 폭탄 튕김, 무기 수치 조절 등의 예시가 있다.

**판 외부: 업적과 아티팩트**

- 영구 재화는 없다. 업적을 달성하면 아티팩트가 해금되어 이후 판의 상점이나 보상 풀에 추가된다.
- 아티팩트는 판도를 바꾸지 않는 작은 변화만 준다. 해금은 "강해진다"가 아니라 "새로운 조합을 시험할 수 있다"는 보상이다.
- 특정 스테이지 이후에만 등장하는 아티팩트를 둔다. 초반 난이도를 보호하고, 후반 진행에 새로운 느낌을 준다.

| 업적 예시 | 해금 아티팩트 (예시) | 등장 조건 |
| --- | --- | --- |
| 누적 처치 1,000마리 | 폭발 범위 표시가 조금 더 빨리 보임 | 전 스테이지 |
| 한 폭탄으로 5마리 동시 처치 | 다중 처치 시 재화 소량 추가 | 전 스테이지 |
| 과열 3단계 도달 후 탈출 | 과열 게이지 상승 속도 소폭 감소 | 2스테이지 이후 |
| 4스테이지 첫 등장 적 100마리 처치 | 해당 적 처치 시 짧은 이동 속도 증가 | 4스테이지 이후 |
| 하드모드 1스테이지 클리어 | 대체 무기 외형 | 하드모드 |

## 기술 설계

모든 밸런스 값은 코드가 아닌 데이터에 두고, 시스템끼리는 이벤트로만 연결한다. 개발 후반이 밸런싱 위주가 되므로, 수치를 바꿀 때 코드를 건드리지 않는 구조가 곧 일정 관리다.

| 시스템 | 구현 방식 | 포트폴리오 어필 포인트 |
| --- | --- | --- |
| 데이터 | ScriptableObject로 무기, 적, 웨이브, 스테이지, 아티팩트 정의 | 기획자가 코드 없이 밸런싱 가능한 구조 |
| 웨이브 편집 | 커스텀 에디터 창에서 웨이브별 적, 수, 위치, 타이밍 편집 | 툴 제작 역량. 밸런싱 속도 향상 |
| 전투 이벤트 | 피격, 처치, 폭발을 이벤트로 발행하고 업적, UI, 재화가 구독 | 결합도 낮은 설계. 실드 등 확장 대비 |
| 적 AI | 적마다 상태 머신(이동, 예고, 공격, 사망) | 예고 동작을 공통 상태로 강제 |
| 폭발 판정 | Physics2D 원형 범위 검사, 할당 없는 버전 사용 | 적 수백 마리 상황의 성능 관리 |
| 풀링 | Unity ObjectPool로 폭탄, 적, 이펙트 재사용 | WebGL 환경 GC 스파이크 방지 |
| 타격감 | 히트스톱, 카메라 흔들림, 폭발 파티클, 사운드 | 게임 필 구현 역량 (Dowtween 패키지 활용) |
| 저장 | 업적과 해금 정보를 로컬 저장 (웹 빌드는 브라우저 저장소 사용) | 웹 빌드 환경 대응 |

**디버그 도구**

- 게임 중 폭탄 딜레이, 폭발 범위, 스폰 밀도를 슬라이더로 바꾸는 개발자 패널을 만든다.
- 1초 딜레이 검증과 과열 곡선 조정에 쓰고, 포트폴리오 영상에서 "밸런싱을 어떻게 했는지"를 보여주는 자료로도 쓴다.

**성능 목표**

- 웹 빌드에서 화면 내 적 200마리, 60fps 유지를 목표로 한다. 수치는 1주차 프로토타입에서 측정 후 조정한다.

## AI 활용 계획

구조와 판단은 직접, 반복 구현과 에셋 초안은 AI에게 맡긴다. 이 분담 자체를 README에 설계 의도로 기록한다.

| 영역 | 직접 | AI 협업 |
| --- | --- | --- |
| 설계 | 데이터 구조, 이벤트 구조, 적 상태 머신 틀 | 구조 검토, 대안 비교 |
| 구현 | 폭탄 판정, 과열 시스템 등 핵심 로직의 최종 검증 | 적별 행동 코드, UI 연결, 에디터 툴 보일러플레이트 |
| 밸런스 | 딜레이, 과열 곡선, 웨이브 조합 최종 결정 | 곡선 초안, 수치 시뮬레이션 스크립트 |
| 아트 | 스프라이트 정리, 애니메이션 프레임 보정 | 캐릭터, 적, 타일 픽셀아트 초안 생성 |
| 콘텐츠 | 업적 조건, 아티팩트 효과 확정 | 아티팩트, 특수 능력 아이디어 후보 대량 생성 |

**기록 규칙**

- AI 결과를 고치거나 버린 순간을 개발 일지에 한 줄씩 남긴다. 예: 문제, 원인, 직접 바꾼 방식, 결과 수치.
- 생성형 아트 사용 사실은 잇치 페이지에 명시한다.
